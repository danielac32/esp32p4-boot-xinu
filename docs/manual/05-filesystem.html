Capítulo V — Sistema de archivos (FAT / microSD)

Objetivo. Explicar la cadena de almacenamiento, la API fl_*, la concurrencia (FatFs + bus SDMMC compartido con WiFi), las trampas reales del port y cómo lo usan shell, kernel y apps. Código: device/sdmmc-esp32p4, device/sdblock-esp32p4, device/fat, fatfs/, device/lvgl/lvglfs.c.

1. Cadena y montaje

microSD (SDMMC slot 0)  +  ESP32-C6 WiFi (slot 1)
        │                          │
        └──── SDMMC host (compartido, sdmmcBusLock) ────┘
                        │
                     sdblock (SD0, bloques 512 B)
                        │
                     fat (FAT0) + fatfs/fl_*  → volumen montado al init si hay tarjeta
                        │
                  lvglfs (letra S:)  → LVGL carga S:/... (imágenes SJPG)

Orden en xinu.conf/devtab: SDMMC0 antes de SD0, SD0 antes de FAT0. sysinit() llama init de cada device; fatInit adjunta el medio y monta si está disponible. fs_mounted() (fsutil) indica si hay volumen. Rutas absolutas estilo /apps/miapp/app.txt, /wifi.txt; fs_resolve normaliza (colapsa ./..).

3. Concurrencia: dos niveles de candado

  • FatFs interno: fl_attach_locks / fatmon (monitor reentrante) serializa operaciones fl_*. Permite llamar desde distintos contextos sin corromper el estado de la librería (las llamadas se toman/sueltan por operación).
  • Bus SDMMC compartido: sdmmcBusInit/Lock/Unlock (system/sdmmcbus.c) serializa el controlador entre microSD (slot 0) y ESP32-C6 WiFi (slot 1). E/S de ficheros compite con SDIO → latencia variable. En audio/UI/red, trocea lecturas largas y haz sleep/yield para no ahogar reproducción ni red.

4. Trampas reales (medidas) — disciplina obligatoria

  • NO trunca al sobrescribir con menos bytes. Si abres un fichero existente y escribes menos de lo que tenía, queda cola vieja y el tamaño antiguo. Mitigación: fl_remove(ruta) antes de fl_fopen(ruta,"w") cuando sustituyes contenido completo (patrón en httpapi PUT, udpserver, settings al guardar /wifi.txt). Toda ruta nueva que sobrescriba debe seguir esto.
  • No existe fl_rename(). No hay publicación atómica: copia → verifica tamaño → borra origen/temporal según el caso (con cuidado de candados).
  • Rutas inválidas / sin montar: comprueba fs_mounted() y resuelve con fs_resolve; maneja errores de fl_fopen/opendir.
