1.2 Formato de instalación: /apps/<dir>/

/apps/miapp/app.elf      → binario ET_REL RV32 (ld -r)
/apps/miapp/app.txt      → metadatos (launcher)
/apps/miapp/icon565.bin  → icono rápido RGB565 LE 96×96, 18432 B, sin cabecera (preferido)
/apps/miapp/icon.jpg     → fallback (SJPG/JPG, decode LVGL, más lento)

app.txt:

name=Mi App
exec=/apps/miapp/app.elf
icon=S:/apps/miapp/icon.jpg
color=0x6688AA

exec es la identidad ante appmgr (se reutiliza slot por ruta): la app debe registrarse con la misma ruta. El launcher prefiere icon565.bin (cacheado en PSRAM como lv_img_dsc_t, sin decode SJPG desde SD) y si no existe usa icon=.

2. Cómo funciona el mecanismo (profundidad)

2.1 appmgr — el registro cooperativo

Tabla fija table[APPMGR_MAX] (8) en el kernel, exportada. Sin MMU → kernel y apps comparten memoria; basta con llamadas exportadas. Estados: APP_FREE, APP_RUNNING (al frente, pinta/atiende gestos), APP_BACKGROUND (UI oculta, puede seguir viva — música), APP_CLOSING (cierre pedido, la app limpia y sale).

FunciónQué haceQuién la llama
appmgr_register(name,path,color,tid)Reutiliza slot por path o toma uno libre; guarda nombre/path/color/tid, state=APP_RUNNING.La app, al arrancar
appmgr_unregister(slot)Marca APP_FREE.La app, al salir
appmgr_get_state/set_stateLee/escribe estado (la app obedece CLOSING; pasa a BACKGROUND al ocultarse).App, launcher
appmgr_request_close(slot)Pone APP_CLOSING (cooperativo).Launcher (cerrar)
appmgr_take_foreground(slot)Slot→RUNNING, otras RUNNING→BACKGROUND.Launcher (retomar/lanzar)
appmgr_find_path/find_tidLocaliza ranura.Launcher, app_runner
Cooperativo, no destructivo. El launcher no hace kill(): pide APP_CLOSING y la app limpia (LVGL, audio, hilos, unregister) y hace exit(). El gesto de sistema es borde inferior → arriba (ev.edge == UI_EDGE_BOTTOM && ev.dir == UI_DIR_UP).

2.2 El launcher: de un toque a ejecutar el ELF

  1. Descubrimiento: fl_opendir("/apps")/fl_readdir; por cada dir lee /apps/<dir>/app.txt → app_info{name,exec,icon,color} (excluye launcher).
  2. Home paginado: grilla 2×3 (6 por página), swipe izq/der cambia página. Icono: intenta icon565.bin → carga chunked a PSRAM (fuera de lvgl_lock) y muestra con lv_img_dsc_t; si no, lv_img con S: (SJPG).
  3. Lanzar/retomar: si hay slot por exec → take_foreground + mostrar; si no → create(app_runner, ..., 1, exec) + oculta launcher. app_runner hace elf_run(path,0,NULL) en su hebra; al terminar (exit→kill) el kernel libera la imagen ELF en PSRAM.
  4. Fondo/switcher: apps pasan a BACKGROUND con borde-inferior↑. En switcher, borde-inferior↑ vuelve al home; resume/close cooperativo.
static int app_runner(char *path) {
    int r = elf_run(path, 0, NULL);
    if (SYSERR == r) { int slot = appmgr_find_path(path); if (slot >= 0) appmgr_unregister(slot); }
    return 0;
}

3. Cómo se hicieron las apps nuevas (y la API nueva)

3.1 API nueva ui_* / statusbar_* (refactor + compat)

Las librerías compartidas en apps/lib/ se refactorizaron a una API clara manteniendo compatibilidad con los nombres viejos:

  • Entrada/gestos: gestos.* expone ui_* (ui_input_t, ui_event_t, ui_create_ex/poll/button/root/show/destroy, UI_EVENT_*/UI_DIR_*/UI_CHROME_*) y conserva gestos_*/GE_*/gev_t. El evento lleva tipo, dir, id, x1,y1,x2,y2,dx,dy y edge (UI_EDGE_BOTTOM/TOP/LEFT/RIGHT/NONE) para detectar gestos desde bordes (p. ej. “volver”/sistema). Callbacks LVGL (corren en lvglui) solo apilan en un anillo SPSC; la app consume con ui_poll().
  • Estado: estado.* expone statusbar_* y conserva estado_*. Muestra IP, WiFi (RSSI con wifiSignalRead/Quality, muestreo gateado por millis() porque el RPC al C6 puede bloquear ~1 s), batería (/dev/power0 POWER_CTRL_PERCENT), enlace (espethLinkIsUp). Se actualiza con statusbar_refresh() (barato, pensado para el bucle).
ui_input_t *ui = ui_create_ex(UI_CHROME_NONE);
statusbar_t *sb = statusbar_create(ui_root(ui), 8, 8, 304);
for (;;) {
    statusbar_refresh(sb);
    ui_event_t ev;
    if (!ui_poll(ui, &ev)) { sleep(50); continue; }
    if (ev.tipo == UI_EVENT_SWIPE && ev.edge == UI_EDGE_BOTTOM && ev.dir == UI_DIR_UP) {
        /* gesto de sistema: ir a fondo (cooperativo) */
    }
}
statusbar_destroy(sb);  /* hijo del root: destruir ANTES de ui_destroy */
ui_destroy(ui);
Reglas de la API/LVGL: lvgl_lock() no es recursivo. Los callbacks solo encolan (nunca exit()/I/O pesada/bloqueos dentro). La app no llama lv_timer_handler() (lo bombea lvglui). Sin estáticas mutables en el ELF: estado en psram_malloc(). Al cambiar la lib compartida, recompila y sube todas las apps (se enlaza en cada ELF con ld -r).

3.2 snake — juego (rendimiento + controles)

Objetivo: Snake jugable, cooperativo. Cómo se hizo: rejilla LVGL (objetos coloreados) de 12×16; estado (body[], dir, comida, score, alive) en PSRAM. Rendimiento: al principio redibujaba las 192 celdas cada paso bajo lvgl_lock (ahogaba a lvglui/entrada) → se cambió a dibujo incremental (solo cabeza nueva, cabeza vieja→cuerpo, cola borrada o comida; grid completo solo en reset). Controles: D-pad con ui_button + swipes de dirección (el fondo capta gestos). Ciclo: registra en appmgr; borde inferior↑ → oculta (ui_show(0)), APP_BACKGROUND y espera cooperativa; APP_CLOSING → limpia y exit(0). sleep(40) por iteración, paso ~240 ms.

3.3 photos — galería (rejilla + grande, assets rápidos)

Objetivo: mostrar las fotos de la SD como galería (miniaturas y, al tocar, grande) sin congelar el sistema. Problema de HW: decodificar JPEG grande en runtime (CPU + lectura SD + flush SPI PIO, LCD DMA retirado) es muy lento y puede no renderizar → solución: preconvertir a RGB565 raw (.565) escalado.

  • Fuente única: escanea /img (JPG en la SD). Resuelve por nombre base: miniatura /img565/thumb/pNN.565 (96×72) y grande /img565/pNN.565 (320×240); o hermano .565. Si no hay .565, fallback S:/img/pNN.jpg (LVGL FS/SJPG, lento).
  • Pipeline (host, proyecto): tools/mkphoto565.py genera sd/img565/*.565 y sd/img565/thumb/*.565 desde sd/img/*.jpg. Se copian a la SD real (cp -r sd/img565 /ruta/a/SD/) para verlas fluidas.
  • Render: buffers en PSRAM (9×13824 B miniaturas + 153600 B grande). Carga chunked con fl_fread fuera de lvgl_lock, luego lv_img_set_src con lv_img_dsc_t (LV_IMG_CF_TRUE_COLOR, RGB565 LE, LV_COLOR_16_SWAP 0). Sin decodificador en runtime para .565.
  • UI/gestos: rejilla 3×3, tarjetas polaroid vintage = ui_button (tap → grande), izq/der página. Grande centrada: izq/der prev/next; arriba o abajo = volver a rejilla; borde inferior↑ = fondo (desde rejilla). Navegación cooperativa con appmgr.
Detalle de la API/LVGL y la receta genérica de app: cap. XI. Para rendimiento (DMA LCD evaluado, PIO estable): ver cap. XI §7.

4. Guía: crear una app nueva con pantalla (paso a paso)

A — Diseña. nombre/ruta /apps/miapp/app.elf, pantallas, IDs de botones, datos (estado en PSRAM) y servicios (FAT fl_*, wifinet, appmgr, audio).
B — Estructura. examples/p4-elfsdk/apps/miapp/{miapp.c,Makefile}, reusa ../lib/start.o y ../lib/gestos.o ../lib/estado.o (API ui_*/statusbar_*).
C — Estado en PSRAM (sin estáticas mutables).
#include <kernel.h>
#include <memory.h>
#include <timer.h>
#include <appmgr.h>
#include "gestos.h"   /* ui_* + compat */
void exit(int codigo);

struct miapp {
    ui_input_t *ui;
    int slot;
    int pantalla;
    volatile int accion;  /* callbacks solo señalan; main actúa */
};
D — UI con ui_* y LVGL (bajo lock, sin llamar LVGL profundo desde callback).
static void ver_home(struct miapp *m) {
    ui_buttons_clear(m->ui);
    /* crear labels/botones con ui_button(...) o LVGL bajo lvgl_lock() */
    ui_button(m->ui, 1, "OK", 40, 180, 240, 55, 0x2A6A9A);
    m->pantalla = 0;
}
E — Bucle cooperativo.
for (;;) {
    int st = appmgr_get_state(m->slot);
    if (st == APP_CLOSING) break;
    while (ui_poll(m->ui, &ev)) {
        if (ev.tipo == UI_EVENT_SWIPE && ev.edge == UI_EDGE_BOTTOM && ev.dir == UI_DIR_UP) {
            ui_show(m->ui, 0); appmgr_set_state(m->slot, APP_BACKGROUND); /* fondo */
        }
        /* ... botones/gestos ... */
    }
    /* si vuelve APP_RUNNING: ui_show(m->ui,1) */
    sleep(40);
}
/* limpiar: statusbar_destroy antes de ui_destroy, unregister, psram_free, exit(0) */
F — Makefile (patrón medido). RV32IMAF ilp32f, -fno-pic -mno-relax -msmall-data-limit=0, ld -r.
OBJS = miapp.o ../lib/gestos.o ../lib/estado.o ../lib/start.o
miapp.elf: $(OBJS)
	$(LD) -r -o $@ $(OBJS)
G — Compilar, instalar, probar.
cd examples/p4-elfsdk/apps/miapp && PATH=/opt/riscv32/bin:$PATH make
curl -X POST "http://<IP>/api/mkdir?path=/apps/miapp"
curl -X DELETE "http://<IP>/api/file?path=/apps/miapp/app.elf"; sleep 1
curl -X PUT -T miapp.elf "http://<IP>/api/file?path=/apps/miapp/app.elf"
# icono rápido: python3 ../tools/mkicon565.py icon.png icon565.bin
printf "name=Mi App\nexec=/apps/miapp/app.elf\ncolor=0x6688AA\n" \
 | curl -X PUT --data-binary @- "http://<IP>/api/file?path=/apps/miapp/app.txt"
Checklist. Sin estáticas mutables (estado en PSRAM) · register/unregister con la ruta exacta · obedece APP_CLOSING y fondo cooperativo · callbacks solo señalan · lvgl_lock no recursivo · I/O FAT fuera del lock · fl_remove antes de sobrescribir · exit(0) desde main (nunca desde callback).
