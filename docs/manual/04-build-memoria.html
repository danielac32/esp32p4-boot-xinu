Capítulo IV — Build, linker y mapa de memoria

Objetivo. Explicar cómo se compila y flashea el sistema, qué define platformVars/xinu.conf, y cómo el ld.script organiza memoria (XIP, L2MEM, PSRAM, reservas DMA, banda fantasma, heap). Quién lo usa: quien compila/flashea y quien depura memoria/DMA/ELF.

1. Flujo de compilación

cd /home/daniel/xinu-p4.2/compile
make ESPTOOL=/home/daniel/esp-idf-py/bin/esptool           # compila kernel
make ESPTOOL=/home/daniel/esp-idf-py/bin/esptool flashxinu # flashea + hard reset
make ESPTOOL=... sbl   # SBL (machine/)
make ESPTOOL=... ulp   # ULP (machine/)
  • compile/Makefile: PLATFORM=esp32p4, BOOTIMAGE=xinu.boot, TOPDIR=... Incluye platformVars. CFLAGS base: -Os -Wall -Wstrict-prototypes -nostdinc -fno-builtin -fno-strict-aliasing -fno-common -ffunction-sections -fno-pic -fwrapv -std=gnu11. Enlaza con --static --gc-sections. DEPFLAGS vacío → cambios en headers no fuerzan recompilar: tras tocar .h o ld.script usa make clean.
  • compile/platforms/esp32p4/platformVars: -march=rv32imafc_zicsr_zifencei -mabi=ilp32f -O2 -ffreestanding, -D_XINU_PLATFORM_ESP32P4_ -DTARGET_SOC_ESP32P4, includes ($(TOPDIR)/lvgl, $(TOPDIR)/fatfs -DFATFS_INC_TEST_HOOKS; ojo: include primero → <lvgl.h> del device). APPCOMPS=shell apps fatfs network mailbox lvgl. DEVICES=uart/tty, psram, nam, lcd/sdmmc/sdblock/fat, gpio, i2c, touch, power, lvgl, audio, sdio/espeth, raw/udp/tcp/telnet. Sin -lgcc: helpers van a ROM por PROVIDE en ld.script (evita libgcc D/C y fallos medidos); excepción __truncdfsf2 en lib/libxc/compiler_rt.c. Construye SBL/ULP vía machine/Makefile.
  • xinu.conf → conf.c/conf.h: generados por el configurador; definen devtab, NDEVS, nombres (SERIAL0,ETH0,AUDIO0,...). No editar conf.c.
  • Herramientas: esptool (venv), serie /dev/ttyACM0 115200 (un solo proceso). Tras reset el CDC puede requerir resincronizar (esptool ... chip_id). Compilador apps ELF: riscv32-unknown-elf-gcc/ld.

2. Linker script (compile/platforms/esp32p4/ld.script)

2.1 Regiones

RegiónORIGINLENGTH (script)Uso
FLASH (rx)0x4000500031M (declarativo; flash física 16 MB)XIP: .init/.text/.rodata (ENTRY(_start)).
RAM (rwx)0x4800000032M−32K (tope 0x49FF8000)PSRAM cacheada (0x48). Reserva al LP al final (acordado con ulp.ld).
HP_L2MEM (rwx)0x4FF00000768KReserva fantasma, vectores, .data/.bss, pila core1, heap kernel.
LP_SRAM0x5010800032KSRAM del LP.
FLASH/RAM son declarativos (sobredimensionados). _psram_free_end = ORIGIN(RAM)+LENGTH(RAM): subir LENGTH(RAM) puede solapar la RAM del ULP.

2.2 PROVIDE y ROM

Bases de periféricos (símbolos tipo SDMMC,CACHE,HP_SYS_CLKRST,GPIO,IO_MUX,UART0), helpers de matriz GPIO ROM, y tabla de rutinas ROM (aritmética/conv/shifts RV32) para evitar -lgcc y fallos con D/C.

2.3 Secciones y símbolos (lógica)

  • Flash: .init, .text, .rodata, ctors, _etext.
  • PSRAM NOLOAD, alineado 4K (DMA con direcciones 0x48; CPU toca 0x88 directo, sin compartir línea con heap):
    • .audioshare: desc/buf TX (4K+8K) + anillo stream (desc 4K + buf 64K) + anillo captura (4K+64K). Evita corrupción medida por cabeceras de heap en la misma línea de caché.
    • .sdshare: _sd_desc_page (4K) + _sd_block_page (4K). _psram_free_start = _sd_block_page+4096.
  • L2MEM: .l2reserve (NOLOAD, 128 KB, 0x20000) para la banda fantasma 0x4FF00000–0x4FF1FFFF (no fiable con caché, medido). .vectors (tabla HW CLIC). .data (VMA L2MEM, LMA flash, _data_loadaddr, __global_pointer$). .bss. .core1stk (NOLOAD, 2K, fuera de .bss para preservar testigo). _end.
  • Heap: _l2mem_free_start=_end, _l2mem_free_end=0x4FFB0000 (top 64 KB reservados a ROM). PSRAM libre: [_psram_free_start, _psram_free_end).

3. Mapa operativo y coherencia

ZonaUsoCuidado
L2MEM heap (~448 KB)Pilas de hilos, memget, tablas/buffers pequeñosNo usar <0x4FF20000 ni top 64 KB; no buffers DMA grandes
PSRAM (~31.8 MB)psram_malloc: PCM, imágenes, estado de apps, caches; páginas NOLOAD DMADisciplina 0x48/0x88; no solapar reservas/ULP
Flash XIP.text/.rodataEscritura en runtime requiere driver/plan; sin tabla de particiones

Alias 0x48/0x88: misma celda (cacheada/directa). DMA: CPU por 0x88, motor por 0x48, fence rw,rw antes de ceder owner, descriptores en páginas reservadas NOLOAD (patrón .audioshare/AHB-DMA→I2S). ELF: se ejecuta por 0x88 pero requiere wb+inv L1D/L2 previo (líneas sucias en 0x48 pueden pisar). L2MEM no tiene alias directo equivalente para DMA.
