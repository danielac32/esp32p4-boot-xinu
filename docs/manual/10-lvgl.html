Capítulo X — Manual de LVGL (aprender a usar y crear pantallas)

Propósito. Este capítulo es un manual práctico para aprender a usar LVGL v8 dentro de Xinu-P4.2: cómo está integrado, qué reglas seguir, cómo crear objetos y pantallas, cómo manejar eventos, qué estructura de datos usar en una app ELF, y ejemplos completos. Todo lo aquí descrito corresponde al port real (device/lvgl/, examples/p4-elfsdk/apps/lib/gestos.*, apps en /apps/).

1. Cómo está integrado LVGL en este sistema

1.1 Componentes

ComponenteUbicaciónFunción
Librería LVGL v8lvgl/ (vendor)Motor gráfico (objetos, estilos, layouts, timers, render).
Port / devicedevice/lvgl/lvglport.c, lvglfs.c, include/lvgl.hConecta LVGL al LCD (flush) y al touch (input), avanza el tick y bombea timers, serializa el acceso.
Hebra de UIlvglTask() → nombre "lvglui" (8 KB pila, LVGL_TASK_MS=5)Llama lvgl_lock(); lv_tick_inc(...); lv_timer_handler(); lvgl_unlock(); sleep(5) en bucle. Es quien refresca la pantalla y ejecuta callbacks de LVGL.
Exclusiónlvglmon (monitor) → lvgl_lock()/lvgl_unlock() (exportados)LVGL no es reentrante: toda llamada a su API debe serializarse.
Salidalvgl_flush_cb → control(LCD0, LCD_CTRL_BLIT, &b, 0)Envía el área renderizada (RGB565) al ST7796 por SPI2. Mantiene lvgl_shadow (320×480 RGB565 en PSRAM) para capturas.
Entradalvgl_touch_cb → control(TOUCH0, TOUCH_CTRL_READ, &pt, 1)Entrega PRESSED/RELEASED + coordenadas. Gestiona apagado por inactividad/despertar.
FS para imágeneslvglfs.c (letra S:)Permite lv_img_set_src(img, "S:/apps/x/icon.jpg") (SJPG con LV_USE_SJPG).

1.2 El modelo de ejecución (lo más importante)

Regla de oro. Solo la hebra lvglui debe ejecutar lv_timer_handler() (lo hace el port). Las apps NO llaman a lv_timer_handler() ni a lv_tick_inc(). Los callbacks de eventos de LVGL (click, value changed, ready del teclado, etc.) se ejecutan dentro de lv_timer_handler(), es decir, en la hebra lvglui y con lvglmon ya tomado.

Consecuencias obligatorias:

  • Desde tu hebra (el main de la app, un hilo reproductor, etc.): rodea toda llamada a API LVGL con lvgl_lock(); ... lvgl_unlock();. Ej.: crear widgets, lv_label_set_text, lv_obj_del, leer lv_textarea_get_text si lo haces fuera de callback (o hazlo con cuidado).
  • Desde un callback LVGL: NO llames a lvgl_lock()/lvgl_unlock() (no es recursivo) y NO llames a funciones que lo tomen (p. ej. helpers de gestos que hacen lock internamente — lee gestos.h: los callbacks de gestos solo encolan). NO llames a exit() desde un callback: exit() → kill(gettid()) mataría lvglui (la hebra actual), no tu app, y corrompería la UI.
  • Patrón correcto desde callback: solo señalar (poner un flag volatile, guardar un dato ya preparado) y que el bucle de main de tu app procese la acción (conectar WiFi, escribir fichero, cerrar).
  • Minimiza el tiempo con el lock tomado: no hagas I/O de SD, sleep largos ni trabajo pesado dentro de la sección crítica. Para animaciones/espectros, actualiza con throttling (p. ej. cada 50–100 ms) y solo si visible.

1.3 Memoria y objetos LVGL

LVGL usa su heap interno (configurado en lv_conf.h, alimentado desde PSRAM en este port) más los buffers de dibujo en PSRAM (DRAW_LINES, doble buffer). Los objetos lv_obj_t* viven en el heap de LVGL; tu app solo guarda punteros a ellos. Borrar el padre borra hijos (lv_obj_del / lv_obj_clean). Al salir, destruye la UI que creaste (gestos_cerrar lo hace para lo de gestos) antes de exit().

3. Usar la librería gestos (recomendada para apps con touch)

gestos (examples/p4-elfsdk/apps/lib/gestos.c/h) simplifica el touch: crea un fondo, clasifica gestos y entrega eventos por un anillo que consumes en tu bucle (modelo hebra-seguro respecto a callbacks LVGL).

gestos_t *gestos_nueva(void); gestos_t *gestos_nueva_partes(int partes);
void gestos_cerrar(gestos_t*); int gestos_leer(gestos_t*, gev_t *out);
void gestos_boton(g,id,texto,x,y,w,h,color); void gestos_boton_en(g,raiz,...);
void gestos_botones_limpiar(g); void gestos_nota(g,texto); void gestos_pastilla(g,texto);
lv_obj_t *gestos_raiz(g); void gestos_show(g, mostrar);

Eventos (gev_t): tipo = GE_NADA, GE_ARRASTRE, GE_TOQUE, GE_LARGA, GE_BOTON; campos dir (GE_ARRIBA/ABAJO/IZQ/DER), x1,y1,x2,y2,dx,dy, id. gestos_leer devuelve 1 si había evento (lo saca), 0 si no.

/* Bucle típico de app */
for (;;) {
    gev_t ev;
    if (appmgr_get_state(mi_slot) == APP_CLOSING) break;  /* cierre cooperativo */
    if (!gestos_leer(g, &ev)) { sleep(50); continue; }    /* sin evento: ceder CPU */
    if (ev.tipo == GE_BOTON) { /* ev.id → acción */ }
    else if (ev.tipo == GE_ARRASTRE && ev.dir == GE_ARRIBA) { /* p. ej. ir a fondo */ }
}

Importante: gestos_cerrar(g) se llama desde tu bucle/main antes de exit(), nunca desde un callback LVGL. gestos_boton*/limpiar manipulan LVGL internamente (toman lock) — llámalos desde tu hebra, no desde un callback.

4. La estructura de estado de una app (struct en PSRAM) — patrón obligatorio

Sin estáticas escribibles de fichero. El cargador ELF de este sistema no aplica R_RISCV_LO12_S; una global/estática mutable produce accesos corruptos. Toda la mutablez va en una estructura asignada en runtime (PSRAM o heap) apuntada por una variable local/puntero.

4.1 Anatomía (basada en struct ajustes de settings.c)

struct miapp {
    /* --- núcleo UI/gestión --- */
    gestos_t    *g;            /* handle de gestos (o NULL si usas LVGL directo) */
    int          slot;         /* slot de appmgr (ciclo cooperativo) */
    int          pantalla;     /* máquina de estados: P_MENU, P_LISTA, P_DETALLE... */

    /* --- punteros a objetos LVGL que necesitas reusar/leer --- */
    lv_obj_t    *titulo;
    lv_obj_t    *estado;
    lv_obj_t    *lista;        /* contenedor scroll */
    lv_obj_t    *campo;        /* lv_textarea, si aplica */
    lv_obj_t    *tecla;        /* lv_keyboard, si aplica */

    /* --- datos de dominio --- */
    int          nitems;
    /* ... arrays/buffers de trabajo (evitan static y malloc repetido) ... */
    char         texto[80];    /* snprintf temporal */

    /* --- señal callback → bucle main (la forma segura) --- */
    volatile int accion;       /* 1 = el teclado/evento pidió hacer algo */
    volatile int dato;         /* payload simple si hace falta */
};

4.2 Por qué cada parte

  • g + slot: UI y registro en el gestor de apps (para que el launcher te retome/cierre cooperativamente y tú obedezcas APP_CLOSING/APP_BACKGROUND).
  • pantalla (máquina de estados): una app real tiene varias vistas. Un enum/#define P_* + una función mostrar_X(m) por vista mantiene el flujo claro. Al cambiar: gestos_botones_limpiar(m->g) (libera IDs/cupo), reconstruye/actualiza widgets y m->pantalla = P_X.
  • Punteros lv_obj_t*: para actualizar texto (lv_label_set_text(m->estado,...) bajo lock desde tu hilo) o leer valores (lv_textarea_get_text) sin buscar en el árbol.
  • Buffers dentro del struct: evitan estáticas y fragmentación; dimensiona al peor caso real (p. ej. 2048 bytes para leer/reescribir /wifi.txt, como hace settings).
  • volatile accion: el único puente seguro callback→main. El callback (en lvglui) hace solo m->accion = 1;; el bucle principal ve el flag, lo limpia a 0 y ejecuta el trabajo pesado (FAT, WiFi wifinet, lógica) fuera del callback y coordinando el lock si toca la UI.

4.3 Cómo se crea y destruye

int main(int argc, char *argv[]) {
    struct miapp *m = psram_malloc(sizeof(*m));   /* o malloc; PSRAM para structs grandes */
    if (!m) exit(1);
    memset(m, 0, sizeof(*m));                     /* estado limpio: punteros NULL, contadores 0 */

    m->g = gestos_nueva_partes(GE_PASTILLA|GE_NOTA);  /* o gestos_nueva() / 0 adornos */
    if (!m->g) { psram_free(m); exit(1); }
    m->slot = appmgr_register("miapp", "/apps/miapp/app.elf", 0x6688AA, gettid());

    construir_ui(m); mostrar_menu(m); m->pantalla = P_MENU;
    bucle_principal(m);

    /* salida ordenada */
    gestos_cerrar(m->g);          /* desmonta UI de gestos */
    appmgr_unregister(m->slot);   /* libera slot */
    psram_free(m);
    exit(0);                       /* kill(gettid): libera la imagen ELF (elf_img) */
}

5. Crear pantallas (patrones concretos)

5.1 Pantalla con botones (usando gestos)

static void mostrar_menu(struct miapp *m) {
    gestos_botones_limpiar(m->g);                 /* reset de la vista */
    gestos_pastilla(m->g, "Mi App");
    gestos_nota(m->g, "Elige una opcion");
    /* gestos_boton(g, id, texto, x, y, w, h, color_rgb565/0xRRGGBB según API) */
    gestos_boton(m->g, 1, "OPCION A",  20, 120, 280, 50, 0x2A6A9A);
    gestos_boton(m->g, 2, "OPCION B",  20, 185, 280, 50, 0x2A6A9A);
    gestos_boton(m->g, 9, "SALIR",     20, 400, 280, 50, 0xC04040);
}
/* en el bucle: if (ev.tipo==GE_BOTON) switch(ev.id) { case 1: ...; case 9: salir; } */

5.2 Pantalla con LVGL directo (etiqueta + actualización desde tu hilo)

static void construir_ui(struct miapp *m) {
    lvgl_lock();
    lv_obj_t *scr = lv_scr_act();                /* o gestos_raiz(m->g) */
    m->titulo = lv_label_create(scr);
    lv_label_set_text(m->titulo, "Estado");
    lv_obj_align(m->titulo, LV_ALIGN_TOP_MID, 0, 10);
    m->estado = lv_label_create(scr);
    lv_label_set_text(m->estado, "Iniciando...");
    lv_obj_align(m->estado, LV_ALIGN_CENTER, 0, 0);
    lvgl_unlock();
}
static void set_estado(struct miapp *m, const char *txt) {
    lvgl_lock();
    lv_label_set_text(m->estado, txt);
    lvgl_unlock();
}

5.3 Entrada de texto con teclado (patrón seguro, como settings)

/* 1) Crear campo + teclado (bajo lock, desde tu hilo al montar la pantalla) */
lvgl_lock();
m->campo = lv_textarea_create(lv_scr_act());
lv_textarea_set_password_mode(m->campo, false); /* visible, útil en touch pequeño */
lv_obj_set_size(m->campo, 280, 40);
lv_obj_align(m->campo, LV_ALIGN_TOP_MID, 0, 60);
m->tecla = lv_keyboard_create(lv_scr_act());
lv_keyboard_set_textarea(m->tecla, m->campo);
lv_obj_add_event_cb(m->tecla, teclado_cb, LV_EVENT_ALL, m); /* user_data = tu struct */
lvgl_unlock();

/* 2) Callback (corre en lvglui, CON lock): NO lock, NO exit, NO I/O pesado */
static void teclado_cb(lv_event_t *e) {
    struct miapp *m = (struct miapp *)lv_event_get_user_data(e);
    lv_event_code_t code = lv_event_get_code(e);
    if (code == LV_EVENT_READY || code == LV_EVENT_CANCEL) {
        m->accion = 1;  /* solo señal; main leerá el texto y actuará */
    }
}

/* 3) En el bucle de main: procesar fuera del callback */
if (m->accion) {
    m->accion = 0;
    const char *txt;
    lvgl_lock();
    txt = lv_textarea_get_text(m->campo);  /* leer bajo lock */
    /* copiar a tu buffer si vas a soltar el lock antes de usarlo */
    strncpy(m->texto, txt ? txt : "", sizeof(m->texto)-1);
    lvgl_unlock();
    /* ahora: conectar, guardar en /wifi.txt, etc. (puede hacer I/O/FAT/red) */
}

6. Ejemplo completo mínimo (app LVGL con gestos + appmgr)

/* miapp.c — esqueleto realista */
#include <stdio.h>
#include <string.h>
#include <kernel.h>
#include <thread.h>
#include <timer.h>
#include <memory.h>
#include <appmgr.h>
#include "gestos.h"

void exit(int codigo);

#define P_HOME 0
#define B_HOLA 1
#define B_SALIR 2

struct miapp { gestos_t *g; int slot; int pantalla; int cuenta; char texto[48]; };

static void pantalla_home(struct miapp *m) {
    gestos_botones_limpiar(m->g);
    gestos_pastilla(m->g, "Mi App");
    gestos_boton(m->g, B_HOLA,  "PULSAME", 60, 180, 200, 60, 0x2A6A9A);
    gestos_boton(m->g, B_SALIR, "SALIR",   60, 260, 200, 50, 0xB04040);
    sprintf(m->texto, "Pulsaciones: %d", m->cuenta);
    gestos_nota(m->g, m->texto);
    m->pantalla = P_HOME;
}

int main(int argc, char *argv[]) {
    (void)argc; (void)argv;
    struct miapp *m = psram_malloc(sizeof(*m));
    if (!m) { kprintf("miapp: sin memoria\r\n"); exit(1); }
    memset(m, 0, sizeof(*m));

    m->g = gestos_nueva_partes(GE_PASTILLA|GE_NOTA);
    if (!m->g) { psram_free(m); exit(1); }
    m->slot = appmgr_register("miapp", "/apps/miapp/app.elf", 0x6688AA, gettid());

    pantalla_home(m);
    for (;;) {
        int st = appmgr_get_state(m->slot);
        if (st == APP_CLOSING) break;                 /* cierre cooperativo pedido */
        if (st == APP_BACKGROUND) { sleep(100); continue; } /* en fondo: no pintar */

        gev_t ev;
        if (!gestos_leer(m->g, &ev)) { sleep(50); continue; }
        if (ev.tipo == GE_ARRASTRE && ev.dir == GE_ARRIBA) {
            appmgr_set_state(m->slot, APP_BACKGROUND);
            gestos_show(m->g, 0);                     /* ocultar al ir a fondo */
        } else if (ev.tipo == GE_BOTON && ev.id == B_HOLA) {
            m->cuenta++; pantalla_home(m);
        } else if (ev.tipo == GE_BOTON && ev.id == B_SALIR) {
            break;
        }
    }

    gestos_cerrar(m->g);
    appmgr_unregister(m->slot);
    psram_free(m);
    exit(0);
}
Al volver de APP_BACKGROUND a APP_RUNNING (el launcher hace take_foreground), tu bucle debe detectar el cambio y llamar gestos_show(m->g, 1) / redibujar según tu diseño (patrón usado en las apps reales).

7. Rendimiento y depuración

  • Lock corto: agrupa cambios de UI en un bloque lock/unlock, pero saca I/O y cómputo pesado fuera.
  • Throttling: espectro/animaciones cada 50–100 ms; solo si la pantalla está visible/foreground.
  • Imágenes: SJPG desde SD es lento (decode CPU + I/O). Para iconos repetidos, cachea RGB565 en PSRAM o usa .bin pre-convertido.
  • Captura de pantalla: lvglShotBmp("/shot.bmp") / API /api/shot del httpd para diagnosticar sin mirar la placa.
  • Si la UI “muere”: revisa si alguien tomó lvgl_lock y bloqueó, si un callback llamó exit()/lock, o si la pantalla se apagó por inactividad.
Resumen de reglas. (1) lvgl_lock/unlock desde tu hebra, nunca en callback LVGL. (2) Callbacks solo señalan (volatile), el trabajo va en main. (3) Nunca exit() en callback. (4) Sin estáticas mutables → todo en struct asignada en runtime. (5) gestos_cerrar + appmgr_unregister + psram_free + exit desde main. (6) Obedece APP_CLOSING cooperativamente.
